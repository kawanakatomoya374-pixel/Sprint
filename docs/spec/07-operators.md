## 7. 演算

### 7.1 算術演算

すべての算術演算はユーザーコードを呼ばず、ヒープ割り当てをしない（H1, A2）。`bool`は数値ではない。

| 演算 | int, int | int/float混在 | float, float | その他 |
|---|---|---|---|---|
| `a + b` `a - b` `a * b` | int。overflowはArithmeticError | intをfloatへ変換して計算 | IEEE-754 | TypeError |
| `a / b` | 常にfloat（両者をfloatへ変換） | float | float | TypeError |
| `a // b` | floor除算でint | `floor(a / b)`をfloatで | 同左 | TypeError |
| `a % b` | floor剰余（結果の符号は`b`と同じ）でint | float版floor剰余 | 同左 | TypeError |
| `a ** b` | §7.2 | `pow(a, b)`のfloat | 同左 | TypeError |
| `-a` | int。`-INT_MIN`はArithmeticError | — | float | TypeError |

- intからfloatへの変換はround-to-nearest-even。
- `/`, `//`, `%`の除数が`0`または`0.0`（`-0.0`を含む）なら**常に**ArithmeticError。
- `INT_MIN // -1`と`INT_MIN % -1`の前者はArithmeticError（overflow）、後者は`0`。
- floatのoverflowは`inf`を生じてよい（エラーではない）。NaNは演算結果として生じ得る。
- float floor剰余の定義: `r = fmod(a, b)`; `r != 0`かつ`r`と`b`の符号が異なれば`r += b`。

### 7.2 べき乗

- int ** int で`b >= 0`: 正確な整数べき乗。overflowはArithmeticError。`0 ** 0 == 1`。
- int ** int で`b < 0`: floatで`pow(a, b)`。`a == 0`ならArithmeticError。
- floatを含む場合: C99 `pow`。結果がNaNになっても例外ではない。

### 7.3 ビット演算

`&` `|` `^` `~` `<<` `>>` はint同士（`~`は単項int）のみ。その他はTypeError。

- 2の補数64bitで計算する。
- `a << n`: `n < 0`はValueError。`n >= 64`の結果は`0`。シフトで溢れたビットは捨てる（エラーではない）。
- `a >> n`: 算術右シフト。`n < 0`はValueError。`n >= 64`の結果は`a < 0`なら`-1`、それ以外`0`。

### 7.4 連結 `..`

- 両operandを`to_string`規則（§6.5）で文字列化して連結する。任意の型を受け付ける（エラーにならない）。
- **割り当て点（A）**。新しい文字列を1つ割り当てる。
- Compilerは`a .. b .. c ...`の連鎖（255項以下）を1命令`CONCAT n`にまとめなければならない（MUST）。連鎖全体で割り当ては1回。256項以上の連鎖は255項ごとに分割し、分割数だけ割り当てる。
- 結果が`max_string_bytes`を超えるならMemoryError（致命的）。

### 7.5 比較 `<` `<=` `>` `>=`

| operand | 規則 |
|---|---|
| 数値同士（int/float混在可） | **数学的に正確な**比較。intをfloatへ丸めてから比較してはならない。NaNを含むと常に`false` |
| string同士 | UTF-8バイト列の辞書順（= code point順）。接頭辞は短い方が小さい |
| その他 | TypeError |

### 7.6 等値 `==` `!=`

`a != b`は常に`not (a == b)`である。等値はエラーを送出せず、ユーザーコードを呼ばず、割り当てをせず、再帰しない。

| 組み合わせ | 結果 |
|---|---|
| 数値同士 | 数学的に正確な等値。`1 == 1.0`は`true`、`0.0 == -0.0`は`true`、NaNを含むと`false` |
| string同士 | バイト列一致 |
| nil/bool同士 | 値一致 |
| 参照型同士（string以外） | 同一オブジェクトなら`true` |
| 型が異なる（数値同士を除く） | `false` |

構造的な比較には`deep_equal(a, b)`（§15.1）を使う。

**連鎖比較（2.3）**: `a < b <= c`のように比較演算子（`==` `!=` `<` `<=` `>` `>=` `in` `not in`）を並べると、`a < b and b <= c`と同じ結果になる。ただし中間の項`b`は**1回だけ**評価され、左から右の順に評価される。前の比較が偽（`and`の短絡）なら、それ以降の項は評価されない。連鎖の長さは最大8個。展開後は隠れた変数と`and`だけで、新しいopcodeはない（結果は最後に評価された比較のbool）。

### 7.7 hashとtable key

- key正規化: 整数値を持ち`int`範囲内のfloatは、key用途でintへ正規化する（`t[1.0]`と`t[1]`は同じkey、`-0.0`は`0`）。それ以外のfloatはそのまま。
- `nil`をkeyにするとTypeError。NaNをkeyにするとValueError。
- string keyはバイト列でhashする。参照型はオブジェクトIDでhashする。
- hash関数とseedは実装定義（§0.4）。反復順は挿入順で固定されるため観測できない。

### 7.8 論理演算と条件式

- `not x`: truthinessの否定（bool）。
- `a and b`: `a`が偽なら`a`、そうでなければ`b`（短絡）。
- `a or b`: `a`が真なら`a`、そうでなければ`b`（短絡）。
- `x if c else y`: `c`が真なら`x`だけ、偽なら`y`だけを評価する。

### 7.9 nil合体 `??`（2.1）

- `a ?? b`: `a`が`nil`ならば`b`、そうでなければ`a`（短絡: `a`が`nil`でなければ`b`は評価されない）。
- `or`との違いは、`false`・`0`・`0.0`・`""`・空のarray/tableを**既定値で置き換えない**こと。`nil`だけを欠損とみなす: `0 ?? 5`は`0`、`false ?? 1`は`false`、`nil ?? nil ?? 7`は`7`。
- 左結合（`a ?? b ?? c`は`(a ?? b) ?? c`）。優先順位は§4.2。割り当て・隠れた制御フロー・ユーザーコード実行はない（`==`と同様に`nil`との比較だけを行う）。
- **`??=`（2.3）**: `a ??= v`は`if a == nil: a = v`の糖衣。`a`が`nil`のときだけ`v`を評価して代入する。`a`は名前、または名前・定数だけから作られる`x.k` / `x[0]` / `x["k"]`の連鎖でなければならない（2回評価されるため。それ以外は`ParseError`）。

### 7.10 パイプ `|>`（2.2）

- `x |> f`は`f(x)`の糖衣。`x |> f(a, b)`は`f(x, a, b)`、`x |> o.m(a)`は`o.m(x, a)`（左辺が**最初の引数**になる）。右辺は後置式で、呼出しの形でなければ（名前・メンバ・括弧で囲んだ式・アロー関数）その値を`x`1つで呼び出す。
- 展開後は通常の呼出しなので、評価順は§5.4のとおり（呼出し先、左辺、残りの引数の順）、割り当て・隠れた制御フローは増えない。spread引数を含む呼出しへのパイプは`ParseError`。
- 左結合: `a |> f |> g(1)`は`g(f(a), 1)`。行頭が`|>`の行は前の行の続きとして読む（インデントは任意）。

```sprint
let r = [1, 2, 3]
    |> sum_of
    |> scale(10)
```

### 7.11 オプショナル連鎖 `?.` `?[]`（2.3）

- `a?.name`、`a?.f(x)`、`a?[i]`: `a`が`nil`なら、**その後ろに続く後置操作の連鎖全体**を評価せずに`nil`にする。そうでなければ通常の`a.name` / `a.f(x)` / `a[i]`と同じ。`nil?.x.y.z`は（`.y`で`TypeError`にならず）`nil`、`t?.a?.b`のように複数書ける。
- 判定は`nil`だけで行う（`false`や`0`は欠損とみなさない）。展開は`{ let $o = a; $o != nil ? $o.name... : nil }`（条件式）で、`a`は1回だけ評価される。新しいopcode・割り当てはない。
- `a?.b = v`のような代入の対象にはできない（`ParseError`）。`defer a?.f()`も書けない（`defer`は呼出し式を要する）。

### 7.12 所属 `in` / `not in`（2.3）

- `x in c`: `c`が配列なら要素に`==`で等しい値があるか、文字列なら`x`（string）が部分文字列か（`""`は常に含まれる）、tableならkey（正規化は§7.7）があるか。それ以外の`c`は`TypeError`。`x not in c`は`not (x in c)`。
- 評価順は`x`、`c`の順。展開は`$in(x, c)`（preludeの隠れた関数で、ユーザーが名前で参照することはできない）。配列の走査はO(n)。`in`の優先順位は比較演算子と同じ（§4.2）。
- `for x in`と内包表記の`for x in`は構文上の別物で、ヘッダの`in`は所属演算子ではない。
