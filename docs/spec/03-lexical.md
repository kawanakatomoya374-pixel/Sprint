## 3. ソースと字句

### 3.1 ソースファイル

- 拡張子`.sp`。エンコーディングはBOMなしUTF-8。BOMがあれば`LexError`。
- 不正なUTF-8シーケンス、U+0000は`LexError`。
- 改行はLF。CRLFはLexer入力前にLFへ正規化する。単独のCRは`LexError`。
- 行番号・列番号は1始まり。列はUnicode code point単位。offsetはUTF-8バイト単位で0始まり。
- 最大サイズは`max_source_bytes`。

### 3.2 インデント（INDENT/DEDENT）

Lexerは次のアルゴリズムでINDENT/DEDENTを生成する。

1. インデントstackを`[0]`で初期化する。
2. 括弧`()[]{}`の内側でも複数行文字列の内側でもない**論理行の先頭**で、先頭の空白数`n`を数える。
3. 空白のみ、またはコメントのみの行は無視する（tokenを生成しない）。
4. 先頭空白にtabが含まれれば`LexError`。空白はASCII space（U+0020）のみ。
5. `n > top`の場合、`n == top + 4`でなければ`LexError`。INDENTを1つ生成しpushする。
6. `n < top`の場合、`n == top`になるまでpopしてDEDENTを生成する。stack中に`n`がなければ`LexError`。
7. 括弧の内側では改行・インデントを無視する。
8. EOFでは、最後の論理行が改行で終わっていなければNEWLINEを補い、stackが`[0]`になるまでDEDENTを生成し、EOFを生成する。
9. 括弧が閉じないままEOFに達したら`ParseError`。

### 3.3 コメント

```text
# 行末まで
#*
  ブロックコメント
*#
```

- `#*`はその行の最初の非空白文字でなければならず、`*#`はその行の最後の非空白文字でなければならない（ブロックコメントは行単位で占有する）。違反は`LexError`。
- ブロックコメントは入れ子にできない。閉じないままEOFに達したら`LexError`。
- コメントだけの行は空行として扱う。

### 3.4 識別子とキーワード

```ebnf
IDENT = ( "_" | "A".."Z" | "a".."z" ) , { "_" | "A".."Z" | "a".."z" | "0".."9" } ;
```

識別子はASCIIのみ（Unicode分類表をVMに持たないため、また同形異字による混乱を避けるため）。非ASCII文字は文字列とコメントの中でのみ使える。

キーワード（識別子として使用不可）:

```text
and as assert break case catch class const continue defer elif else
export extends false for from func if import in let match nil not or
override pass panic return super throw true try while yield
```

- `init`と`self`はキーワードではない。`init`はconstructorメソッド名として、`self`はメソッドの第1引数名として特別な規則を持つ（§10）。
- 次の3箇所に限り、キーワードも名前（`NAME`）として書ける: メンバアクセスの`.`の直後（`t.match`）、table literalのkey（`{match: 1}`）、table patternのkey。いずれも文字列keyとして扱う。

```ebnf
NAME = IDENT | KEYWORD ;
```

### 3.5 数値リテラル

```ebnf
INT     = DEC | HEX | BIN | OCT ;
DEC     = "0" | NZDIGIT , { [ "_" ] , DIGIT } ;
HEX     = "0" , ( "x" | "X" ) , HEXDIGIT , { [ "_" ] , HEXDIGIT } ;
BIN     = "0" , ( "b" | "B" ) , BINDIGIT , { [ "_" ] , BINDIGIT } ;
OCT     = "0" , ( "o" | "O" ) , OCTDIGIT , { [ "_" ] , OCTDIGIT } ;
FLOAT   = DECDIGITS , "." , DECDIGITS , [ EXP ]
        | DECDIGITS , EXP ;
DECDIGITS = DIGIT , { [ "_" ] , DIGIT } ;
EXP     = ( "e" | "E" ) , [ "+" | "-" ] , DECDIGITS ;
```

- `_`は数字と数字の間にのみ1個置ける。
- `0`で始まる2桁以上の10進整数（`077`）は`LexError`。
- floatは小数点の両側に数字が必須。`1.`と`.5`は存在しない（`1..2`を`1 .. 2`と曖昧なく字句解析するため）。
- リテラルは符号を含まない（`-1`は単項`-`と`1`）。整数リテラルの値が`2^63`を超えたら`LexError`。値がちょうど`2^63`のリテラルはLexerが受理し、Parserが「単項`-`のoperandがそのリテラル単体である」場合に限り`INT_MIN`（`-2^63`）として受理する。それ以外の位置では`ParseError`。
- floatリテラルが有限のbinary64で表現できない（overflowしてInfinityになる）場合は`LexError`。丸めはround-to-nearest-even。

### 3.6 文字列リテラル

- `"..."`と`'...'`。生の改行を含めない。
- `"""..."""`と`'''...'''`は複数行文字列。生のLFを含められる。インデントは除去しない。
- エスケープ: `\\` `\"` `\'` `\n` `\r` `\t` `\0` `\xHH`（00〜7Fのみ） `\u{H..HHHHHH}`（Unicode scalar value、サロゲート範囲は不可）。それ以外のエスケープは`LexError`。
- **生文字列（2.3）**: `r"..."` `r'...'` `r"""..."""` `r'''...'''`は`\`を含め一切のエスケープを解釈せず、本文をそのまま値とする。生の改行は三連引用符の形だけが含められる。`r`は直後に引用符が続くときだけ接頭辞になる（`r`単独は通常の識別子）。f-stringとの併用（`rf""`）はない。
- 文字列値は常に正しいUTF-8である。

#### 3.6.1 f-string（2.1）

`f"..."`・`f'...'`・`f"""..."""`・`f'''...'''`（`f`は直後に引用符が続くときだけ接頭辞になる。`f`単独は通常の識別子）。

- 本文は通常の文字列と同じエスケープ規則（§3.6）に従う。
- `{`式`}` の位置で式を評価する。式は通常の式（§4.1の`expression`）で、全体が丸括弧で囲まれたものとして解析される。式の部分は**生のソース**であり、リテラル部分のエスケープ処理（`\n`等）は適用されない。式中に生の改行を置けるのは三連引用符のf-stringだけである。
- 文字としての波括弧は `{{` と `}}` で書く。対応しない単独の `}` は`LexError`。閉じない `{` も`LexError`。`{}`（空の式）と、式として不正な内容は`ParseError`（位置はf-string内の該当位置）。
- 引用符1個のf-stringでは、式の中でそのf-stringを囲む引用符と**同じ種類の引用符**を使えない（`LexError`。別の種類の引用符は使え、f-stringの入れ子も別の種類の引用符で書ける）。三連引用符のf-stringでは制限されない。
- 意味は `"a" .. to_string(e1) .. "b" ..`（§7.4）の連結と**同じ**である。式は左から右へ1回ずつ評価され、連結は1回の割り当て（`CONCAT`、A）で行われる。式の個数の上限は`CONCAT`の上限（§17.4）に従う。
- `f""` は空文字列。

### 3.7 演算子・区切り記号

```text
+  -  *  /  //  %  **  ..  &  |  ^  ~  <<  >>  ??
== != <  <= >  >=
=  += -= *= /= //= %= ..= **= &= |= ^= <<= >>=
(  )  [  ]  {  }  :  ,  .  ...  =>  |>  ?.  ?[  ??=
```

次の字句は存在せず、出現したら`LexError`: `;` `?`（単独） `++` `--` `!` `@` `$` `` ` `` `\`（文字列外）。（2.0では`??`・`=>`もここに含まれていた。`??`は2.1、`=>`と`|>`は2.2、`?.` `?[` `??=`は2.3で演算子になった。`?.`は直後が数字のとき（`a ?.5`）は`?`と`.5`として扱われず`LexError`のままである。）
