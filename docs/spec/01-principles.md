## 1. 設計原則

### 1.1 言語の性格

- **動的型付け**: 値の型は実行時に検査する。変数に型はない。
- **事前コンパイル**: ソースは常に検証済みbytecodeへコンパイルしてから実行する。AST直接評価は公式実行経路にしてはならない。
- **Python風構文**: インデントブロック、読みやすい式。
- **Lua風実行モデル**: 小さなスタックVM、軽量なtable、Cから埋め込みやすいAPI。
- **隠れた制御フローなし**（§1.2）。
- **隠れたメモリ割り当てなし**（§1.3）。
- **決定性**: 同一入力・同一設定・同一処理系では出力・終了コード・順序が再現する。
- **安全な失敗**: 未定義動作、メモリ破壊、暗黙の権限昇格がない。

### 1.2 隠れた制御フローなし（No hidden control flow）

**原則: コードが関数呼出しに見えないなら、ユーザー定義コードは実行されない。コードがジャンプに見えないなら、制御は移動しない。**

処理系は次を保証しなければならない（MUST）。

- **H1** 算術・比較・等値・ビット演算・連結・添字読み書き・メンバ読み書き・`len`・`type`・`to_string`・`print`・ハッシュ計算・GCは、**ユーザー定義コードを一切呼び出さない**。演算子オーバーロード、メタメソッド、getter/setter、ユーザー定義の文字列化、ファイナライザ、暗黙のユーザー定義型変換は存在しない。
- **H2** ユーザー定義コードが実行される地点は、付録Bに列挙した構文・関数に限られる。いずれもソース上で「呼出し」「`for`」「`defer`」「`import`」として視認できる。
- **H3** 非局所的な制御移動は次だけである: `return`, `break`, `continue`, `throw`, `panic`, `yield`, 演算・関数が送出するエラー（付録Bに各演算の送出条件を記載）、`sys.exit`、資源上限超過。
- **H4** エラーが暗黙に捕捉されることはない。自動リトライ、暗黙の再開、暗黙のエラー変換（例: 任意の値を自動でErrorに包む）はない。
- **H5** module初期化はプログラム開始時に決定的な順序で一度だけ行い、遅延初期化しない（§14.5）。
- **H6** `defer`で登録した呼出しは、登録した文と同じブロックの終了時にだけ実行される。登録はソース上で視認できる。

### 1.3 隠れたメモリ割り当てなし（No hidden allocation）

**原則: ヒープ割り当てが起き得る場所は、ソースを読むだけで静的に特定できる。**

- **A1** ヒープ割り当ては、付録Aに列挙した**割り当て点**でだけ起きる。それ以外の操作（関数呼出し、return、算術、比較、ローカル変数操作、メンバ読み、既存要素の添字読み書き、組込みコンテナの`for`反復、`match`、`defer`、`try`の正常経路など）はヒープ割り当てをしてはならない。
- **A2** 値`int`, `float`, `bool`, `nil`はヒープに置かない（§6.2の16バイト値表現）。数値演算は決して割り当てない。
- **A3** 割り当ての可能性がある操作は「必ず割り当てる（A）」と「容量不足時に割り当てる（A?）」の2種に分類する。A?の操作は、事前に`reserve`で容量を確保していれば割り当てないことを保証する（§8）。
- **A4** VMのoperand stack、call frame、defer record、出力バッファは**VM生成時に上限分を一括確保**する。実行中に伸長しない。上限超過は`MemoryError`である。
- **A5** VMが演算失敗を検出してError objectを生成する割り当て（失敗経路の割り当て）は許可する。この割り当て自体が失敗した場合、そのエラーはMemoryError（致命的、§12.6）に置き換わる。正常経路の挙動には影響しない。
- **A6** GCは割り当て点（または`gc.collect()`）でだけ起動する。したがってGC停止も割り当て点でだけ起き得る。
- **A7** C実装においても、処理系はホストが渡したアロケータ（§20.2）以外でメモリを確保してはならない。
- **A8** `sprint lint --alloc`は、ソース中のすべての割り当て点を一覧表示しなければならない（§23.3）。

### 1.4 非目標

Sprint 2.0は次を提供しない: 静的型検査、型注釈、ジェネリクス、演算子オーバーロード、メタメソッド、JIT、共有メモリスレッド、`eval`/reflection、キーワード引数、例外フィルタ構文、バイナリ（bytes）型、正規表現、ネットワークstdlib。
