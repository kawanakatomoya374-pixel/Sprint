# Sprint VM runtime and JIT source map

This directory documents the source layout. Runtime hot paths remain deliberately
in their dispatch/compile translation units when splitting them would add a call
or prevent the compiler from seeing a useful optimization boundary.

## VM runtime

| File | Responsibility | Path frequency |
|---|---|---|
| `src/runtime/vm.c` | Interpreter and computed-goto opcode dispatch | Every interpreted instruction |
| `src/runtime/vm/quickening.c` | Fused-opcode selection and bytecode rewriting | Program load / REPL append |
| `src/runtime/vm/class.c` | Constructor bytecode-shape analysis | First construction / class cache miss |
| `src/runtime/vm/trace_record.c` | Trace recorder TLS state, edge detection and optional path dump | Only when JIT trace recording is enabled |
| `src/runtime/vm/internal.h` | Private declarations shared by the VM modules | Compile time only |

`vm.c` intentionally retains the main computed-goto dispatch loop. Moving opcode
handlers across translation units or routing each recorded instruction through a
function call would add work to the hottest interpreter path and can inhibit the
compiler's dispatch layout optimizations. Trace-step writes therefore remain an
inline macro in `vm.c`; recorder lifetime and reporting are out of line.

## JIT

| File | Responsibility |
|---|---|
| `src/runtime/jit.c` | Copy-and-patch bytecode region compiler, ordinary JIT and region execution |
| `src/runtime/jit_trace.c` | TraceIR-to-native TraceJIT compilation, trace cache and trace linking |
| `src/runtime/jit/regalloc.c` | Shared physical-register bank implementation |
| `src/runtime/jit/internal.h` | Private JIT module interface and common data structures |
| `src/runtime/trace_ir.c` | Trace SSA IR construction, verification and optimization |
| `src/runtime/jit/stencils.S` | Stencil assembly source |
| `src/runtime/jit/stencils.h` | Generated stencil byte table; regenerate with `make jit-regen` |
| `src/runtime/jit/layout.h` | Generated structure offsets used by stencil assembly |

`jit.c` remains a sizeable compiler unit because its bytecode lowering helpers share
a large private compiler state and are candidates for inlining. The TraceJIT and
register ownership responsibilities are separated already; a further split should
be driven by a clear interface and paired runtime measurements, not just line count.

## Generated source data

- `src/lib/font_ja.c` is generated by `tools/genfont.py` and contains bitmap glyph
  data. It is intentionally kept as a single generated data unit.
- `src/runtime/jit/stencils.h` is generated from `stencils.S` by `make jit-regen`.
  Do not hand-edit the generated table.
- `build/` contains local binaries, objects, generated test images and benchmarks;
  it is ignored and must not be included in source archives.

## Historical design notes

Older optimization experiments are kept under `docs/jit/archive/`. Their benchmark
results describe the historical Sprint version stated in each note and must not be
read as current performance claims.

## Trace snapshots

TraceJIT side exits use `src/runtime/jit/snapshot.{h,c}`. Each compiled trace owns
four immutable descriptors: loop-condition exit, arithmetic deoptimization, entry
type-guard miss, and instruction-budget exhaustion. Tokens encode the owning trace
slot and exit kind, so a native-linked side exit is resolved against the trace that
actually returned.

The current snapshot map covers all frame locals plus the active operand-stack prefix.
Loop-carried SSA values are tagged `FROM_IR` and materialized into their VM slots by
the native exit stencil. Values not changed by the trace are tagged `FROM_SLOT` and
remain untouched in the VM stack. Restore validates the frame/prototype/slot shape,
restores the exact bytecode PC, and sets the operand-stack top to
`base + local_count + stack_depth`. Non-empty operand stacks are therefore preserved
without allocation. This TraceIR tier deliberately refuses to pop or rewrite values
from the pre-existing stack prefix; only temporary values above that prefix may be
consumed while recording a loop body.

The map supports numeric, boolean, nil, and all current object-reference `SpType`
values (`T_STRING` through `T_CELL`). Reference PHIs are materialized as raw payloads
while their VM type tags remain in place. Sprint's collector is precise, non-moving
mark/sweep and scans the active VM stack; Trace native code has no GC safepoint or
allocation call, so references remain rooted in their canonical VM slots until the
snapshot exit. `make test-trace-side` also runs the reference variants under
`SPRINT_GC_STRESS=1`.

Snapshot metadata is charged against the per-Proto Trace cache budget and freed on
LRU eviction. The `MISS` descriptor intentionally has an empty rewrite map because
it is taken before native state changes; it must be able to restore the original
value whose type caused the guard miss.

## Side traces

Each Root Trace can own up to four Side Trace children. A child is selected by a
signature over loop-carried local slots, including their exact runtime `SpType`;
string, array, table, nil, and function references can therefore occupy distinct
variants at the same loop site. An unseen signature first exits through the root's
MISS snapshot, records one interpreter iteration from the restored loop header,
and compiles through the same TraceIR and Copy-and-Patch backend. The child owns its
own code mapping, Snapshot tokens, cache slot, signature, and LRU timestamp. Repeated
calls select the matching native child directly.

Root and child traces share the per-Proto 64-slot / 1MiB bounded cache. Evicting a
child detaches only that child and removes its retry-suppression signature; evicting
a root first evicts its children. If no child has the matching signature or the
four-child limit is reached, execution safely falls back to the VM rather than
repeatedly entering a known-mismatching trace. Incoming native links are disabled
when a root becomes polymorphic and are restored to the root when the last child is
evicted. Side-of-Side trees are not yet implemented.

This remains a constrained TraceIR tier, not full LuaJIT parity: the loop condition
is still a canonical numeric two-operand comparison, numeric accumulation is the
optimized work, and reference values are currently supported as loop-carried
pass-through values rather than arbitrary object operations. The recorder also
preserves, but does not rewrite or consume, the pre-existing operand-stack prefix.
The regression `make test-trace-side` covers a linked-target MISS, four reference
Side Trace variants, the four-child fallback, Snapshot materialization, and GC
stress. `make test-trace-side-cache` stresses mixed Root/Side LRU eviction across
70 loop sites.

The dedicated `tools/bench/trace/multi_side_refs.sp` benchmark compares a single
numeric/root-only baseline against a Root with array/table/nil/function Side Trace
variants. On CPU 0 with 13 alternating runs, the median improved from 0.021122s to
0.012144s (1.739x, 73.9% faster), with identical output. The regular `loop`,
`tsieve`, and `matmul` benchmarks stayed within about 1.2% of baseline, so the
measured gain is specific to reference-polymorphic loop workloads.
